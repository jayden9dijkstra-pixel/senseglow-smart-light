
- Private MCP tools (orders, sales, funnel, attribution, ads) query with the caller's OAuth token and require the admin role; why: database RLS stays the single access boundary and no service key is used in MCP.
- Dashboard metrics live as pure functions in src/lib/dashboardMetrics.ts (tested with vitest); edge functions only return raw, PII-free data; why: one tested source of truth for margin, levy and VAT rules.
- Shopify orders sync into shop_orders via supabase/functions/_shared/shopify-orders.ts (cron every 5 min + on dashboard load) and never overwrite stored attribution with empty values; why: attribution is irreplaceable once lost.
- Google Ads daily stats arrive via the ingest-ads function (x-ingest-token = ADS_INGEST_TOKEN) from a Google Ads Script; why: the connector gateway cannot be called from edge functions.
- Dashboard traffic filtering uses `exclude_internal`; reserve `intern` for explicit device marking commands so report filters never change visitor classification.
- Google Ads server conversions are appended to a Google Sheet (service-account JWT, _shared/google-sheets.ts) from the order sync, deduped via ads_conversion_exports and only for orders with recorded ad consent; why: Google Ads imports the Sheet and the connector gateway cannot be used from edge functions.
- The only offer is Shopify's automatic 'Meer lampen' volume discount; its rule and eligible handles live in src/lib/quantityOffer.ts and drive the quantity picker, cart upsell and prerender, while the site never applies discount codes and the cart shows Shopify's own discount lines via a preview cart; ad angles (?a=) in src/lib/angles.ts only preselect the picker; why: Shopify stays the single source of prices and one rule feeds every page.
- Search-intent landing pages are data in src/lib/landingPages.ts (NL only, no hreflang) and rendered by both src/pages/LandingPage.tsx and scripts/prerender.ts; why: one source so server HTML and the live page never diverge.
- Legal/info page bodies live in src/pages/content/*Content.tsx (no layout imports) and scripts/prerender.ts renders them plus the businessInfo footer line into server HTML; cookie choice encoding lives in src/lib/consent.ts; why: one source for client and server HTML, and no asset imports in the prerender.
- Product and landing pages follow one blueprint order (gallery, title, icon benefits, pickers, price, TrustLine, button, How it works, reviews, spec tiles, FAQ, contact, repeat button); benefits and FAQs live in src/lib/productBlueprint.ts and specs are parsed from the Shopify 'Specificaties' block; landing pages put trust and benefits below the button to keep it above the fold; why: one consistent mobile buy flow sourced only from Shopify and existing pages.
- Landing-page photos are selected by Shopify alt text in src/lib/scenes.ts; product galleries preserve Shopify image order regardless of scene parameters and only navigate to variant images after a user selection; why: landing intent and catalog media ordering remain separate.
- Purchase reassurance uses src/lib/purchaseTrust.ts and the owner block uses BehindSenseGlow in client and prerender; why: return-window and identity text stay consistent without invented reviews.
- Customer reviews live only in src/data/reviews.ts and the section hides when it is empty; why: no sample or invented reviews may ever render.
- Scheduled offer display uses explicit dates in quantityOffer plus the shared useOfferDate boundary clock; default rate calculations remain unchanged for tracking, and Shopify still calculates cart discounts; why: temporary presentation must not change checkout or measurement.
- Landing buy buttons share canPurchaseVariant and the selected primary offer's availability; why: the repeated button must never bypass the main button's stock check.
